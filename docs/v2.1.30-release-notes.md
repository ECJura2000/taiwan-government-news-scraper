# 各機關新聞整理 v2.1.30

## 官方 RSS 優先

- 逐一查核既有 88 個來源的新聞頁、訂閱頁及官網首頁，49 個來源設定 RSS 優先。新增 17 個符合原新聞欄目的官方頻道，並採用使用者提供的主計總處 RSS；其餘保留原路徑。完整記錄見 [88 來源查核](RSS_PRIORITY_AUDIT.md)。
- RSS／Atom 根節點驗證優先於機關專用 HTML／JSON 解析；不再把維護頁或一般 XML 當成零篇新聞。
- RSS 最早日期尚未早於指定週起始日、整份 RSS 已過期，或來源設定已標示較窄範圍時，保留 RSS 取得的新聞並接續原路徑。備援失敗會保留已取得新聞及失敗證據，不假裝完整成功。
- 同週比較確認行政院、客委會及交通部 RSS 未包含原列表的部分文章；這三個來源固定補查原列表，維持原收錄範圍。
- 主計總處在一般 HTTP 憑證驗證失敗時，使用正常驗證憑證的 Chrome 讀取原官方 RSS；Chrome 的 XML 顯示內容可還原成 RSS。未擴大國防部既有 TLS 例外。

## 國家標準時間

- 每次執行嘗試以 NTP／UDP 123 連線 `time.stdtime.gov.tw`，失敗依序嘗試 `tock`、`watch`、`clock`、`tick.stdtime.gov.tw`，整體等待不超過約六秒。
- 校正結果套用於預設週別、近期資料判斷、執行紀錄及臺北時間的匯出時間；新聞原發布日期與明確指定的日期區間不受校時改寫。
- 檢查伺服器同步狀態、回應模式、stratum、原始請求時間戳、四時間戳時差、往返延遲及誤差範圍。連線失敗或樣本不合格時，使用系統時間並在 `performance.time_sync` 如實記錄。
- 使用每次執行獨立的校正基準及單調時鐘；不在程式內改動作業系統時間。原本的系統時鐘跳動診斷仍保留。

本版包含 v2.1.29 已合併的全文擷取、品質門檻、效能診斷及日常來源檢查改進。保持 88 個來源、CLI 介面、JSON schema v4、Excel 17 欄及預設全文處理。
